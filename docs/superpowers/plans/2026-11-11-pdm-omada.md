# Omada Section (Phase 1, Read-Only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only "Omada" section in Proxmox Datacenter Manager showing VLANs, physical switch ports, and clients (with PVE-remote annotation), behind PDM's existing TLS + auth.

**Architecture:** A new `server/src/api/omada/` proxy over Omada OpenAPI v1 (token-cached, self-signed-TLS-tolerant `proxmox_client` HTTP client with retry), a new `lib/pdm-config/src/omada.rs` config module (`omada.cfg` + `omada.shadow`), serde response types in `lib/pdm-api-types`, and a new `ui/src/omada/` Yew module registered in the main menu exactly like Notes. Change is additive: new files plus a handful of registration lines.

**Tech Stack:** Rust 2021 workspace (fork of PDM v1.1.9), `proxmox-client 1.0.4`, `proxmox_router`/`proxmox_schema` API macros, Yew 0.21 + `pwt` widget toolkit, WASM via Trunk/proxmox-wasm-builder.

**Spec:** `docs/superpowers/specs/2026-11-11-pdm-omada-design.md` (read it first; it pins every verified Omada API fact used here).

## Global Constraints

- Rust 2021, workspace-only dependencies. Only new dep allowed: `async-trait` in `lib/pdm-api-types/Cargo.toml` (already a workspace dep; see Task 1).
- Additive change. The only shared files touched are: `server/src/api/mod.rs` (1 SUBDIRS line + 1 mod line), `server/src/connection.rs` (1 default trait method + 1 override), `server/src/context/mod.rs` (1 init line), `lib/pdm-api-types/src/lib.rs`, `lib/pdm-config/src/lib.rs`, `ui/src/lib.rs`, `ui/src/main_menu.rs`, `server/tests/common/test_application.rs` (test-only).
- Do **not** add `RemoteType::Omada`; do **not** use the internal `/{omadacId}/api/v2` protocol; do **not** fetch Omada from the browser.
- Serde: every Omada wire type uses `#[serde(default)]` on all fields, `#[serde(rename_all = "camelCase")]`, and allows unknown fields (no `deny_unknown_fields`) — controller schema drift must not break parsing.
- Verified Omada wire facts (from the spec's "Verified facts" section): token header is `Authorization: AccessToken=<token>` (NOT `Bearer`); list endpoints require `?page=N&pageSize=M` (not `pageNo`); error envelope is `{errorCode, msg, result}` with non-zero `errorCode` = error; client pagination total is `result.totalRows`; wired clients carry `switchMac` + `port`.
- Permissions: reads = `Permission::Privilege(&["system"], PRIV_SYS_AUDIT, false)`; config PUT = `Permission::Privilege(&["system", "omada"], PRIV_SYS_MODIFY, false)` (mirrors `server/src/api/config/notes.rs`).
- `PRIV_SYS_AUDIT` / `PRIV_SYS_MODIFY` come from `pdm_api_types` (see `notes.rs` imports).
- Commit style matches `git log`: `area: imperative sentence` (no conventional-commit prefixes). One commit per task (Task 7 may make two).
- First `cargo build` downloads the whole dependency tree; expect several minutes. Subsequent checks are fast.

## Review Focus

Failure modes the spec implies but endpoint tests don't fully exercise. Each has a test added to the owning task where feasible; the rest are verified manually at deploy time.

1. **Token-refresh stampede:** two concurrent requests hitting an expired/absent token must produce exactly one `authorize/token` call (single-flight `tokio::sync::Mutex`). Untested at transport level beyond the Task 3 mock-transport test; a regression means a burst of auth calls every ~2 h.
2. **Controller drops connections under bursty load** (RST/timeout mid-request): the retry-with-backoff path (3 attempts, 200 ms then 1 s, transport errors only). The retry predicate is unit-tested; full timing against a real flaky controller is verified at deploy.
3. **`totalRows` lies (larger than actual rows):** pagination must terminate on an empty page, not loop forever. Tested in Task 3.
4. **Node hostnames that fail DNS resolution** (offline node): the clients endpoint must still succeed and match by literal hostname and node name. Tested in Task 4.
5. **Self-signed TLS certificate:** the upstream client accepts an untrusted cert (callback, modeled on `server/src/connection.rs:1115-1168` `probe_tls_connection`). A regression (e.g. someone "fixes" the cert handling) makes every upstream call fail after cert rotation. Not unit-testable; verify live in Task 7.

Implementation notes:
- Both files are `SectionConfigData` keyed by the single fixed id `omada` (`SectionConfig::parse_section_config::<OmadaRemote>(OMADA_CFG_FILENAME, content)`), modeled on `remotes.rs:105-165`.
- `read()`: parse `omada.cfg` (absent file → `(None, digest of empty)`), then merge `client_secret` from `omada.shadow`; digest is over the **cfg file** content.
- `save()`: strip the secret from the cfg entry (`client_secret = PropertyString::Absent`), write `omada.shadow` first, then `omada.cfg` — same ordering and comments as remotes.rs ("write out cfg *only after shadow config has been written*"). - `init()` holds a `OnceLock<std::sync::Mutex<()>>`; `save()` locks it. Keep it this thin — its only job is to satisfy "init registered in context" (spec).
- Unit tests exercise the *pure* string level (the `configdir!` path is a fixed `/etc/...` path, so don't do file I/O in tests — same reason `remotes.rs` tests only test path logic).

#[async_trait]
pub trait OmadaTransport: Send + Sync {
    async fn request(&self, method: &str, url: &str, headers: &[(&str, &str)], body: Option<&str>)
        -> Result<String, anyhow::Error>;
}

Wire behavior (all pinned by the spec's verified-facts section):
- omadac_id: if `remote.omadac_id` absent → `GET {base}/api/info` (no auth) → `result.omadacId`, cached.
- Token: `POST {base}/openapi/authorize/token?grant_type=client_credentials` with JSON body `{"omadacId", "client_id", "client_secret"}` → `{accessToken, expiresIn: 7200}`; stored as `TokenEntry { expires_at: now + expiresIn }`. Single-flight via the `tokio::sync::Mutex` (hold across check→fetch→store). Refresh when `should_refresh` (5-minute early window).
- Auth header for every `/openapi/v1/...` call: `Authorization: AccessToken=<token>`.
- Site default: `GET /openapi/v1/{om}/sites?page=1&pageSize=50` → first `id`; cached in the `site` mutex for the client's lifetime. `site: Option<&str>` parameter overrides.
- Every list GET appends `page`/`pageSize` params; `?site=<id>` when applicable.
- Envelope (module-level, generic):

```rust
#[derive(Deserialize)]
struct OmadaResult<T> { #[serde(default)] total_rows: u32, #[serde(default)] items: Vec<T> }
#[derive(Deserialize)]
struct OmadaEnvelope<T> {
    #[serde(default)] error_code: i32,   // wire: "errorCode"
    #[serde(default)] msg: Option<String>,
    #[serde(default)] result: Option<OmadaResult<T>>,
}
// error_code != 0  →  bail!("Omada error {error_code}: {msg}")
```

- Pagination: `page` from 1, `pageSize=100`, append `items`; stop when a page's `items` is empty, or `collected >= total_rows`, or `collected >= 2000` (hard cap). Transport-level errors (connection/timeout variants of the client's error — classify in `fn is_transport_error(&anyhow::Error) -> bool`; do **not** retry after a full body was received) are retried up to 3 attempts with 200 ms then 1 s delay.
- `impl OmadaApiClient for OmadaHttpClient` (Task 1 trait) — the four methods are thin wrappers over a private `fetch_all::<T>(path)` + the envelope/pagination machinery. `switch_ports` hits `/openapi/v1/{om}/sites/{site}/switches/{mac}` (no pagination — `portList` comes back in the device record; extract `result.portList` — if the controller returns `items` there instead, adapt; note it in a comment).
